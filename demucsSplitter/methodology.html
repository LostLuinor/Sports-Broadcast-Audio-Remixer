01
Ingestion & Buffering
Live Stream Ingestion
Capture the incoming live video feed, extract audio in real time, and buffer it into overlapping chunks. A deliberate 10-second processing lag is introduced here — the live feed plays ahead while the system works on the buffered window behind it.
⏱
10-Second Lag Window
The live stream is delayed by 10 seconds at the output layer. This window gives the separation model enough time to process each audio chunk and produce clean stems before the remixed audio reaches the viewer. Crossfading at chunk boundaries (50–100 ms overlap) ensures the transition is completely smooth with no audible clicks or seams.

// workflow
Receive Live Stream
Ingest HLS / RTMP stream or local video feed. Extract raw audio at 44100 Hz using FFmpeg with minimal latency flags (-fflags nobuffer).
Chunk & Buffer
Split audio into overlapping 2–4 second chunks with 100 ms crossfade overlap. A circular buffer holds the last 10 seconds for processing.
Sync Video & Audio
Delay video output by 10 seconds using an in-memory frame buffer to stay in sync with processed audio. No re-encoding needed — lossless video copy.
FFmpeg PyAudio / PortAudio Circular Buffer HLS / RTMP Crossfade Overlap-Add
02
Core ML
Source Separation
Each buffered audio chunk is passed through a pre-trained deep learning model to isolate the commentary (vocals) stem from the crowd and ambient background stem independently.
// workflow
Load Pre-trained Model
Use Demucs htdemucs or UVR-MDX-NET-Voc_FT in two-stems mode. Model is loaded once at startup and kept in memory for low-latency inference.
Run Inference per Chunk
Each 2–4 second chunk is processed independently, producing two stems: vocals.wav (commentary) and no_vocals.wav (crowd + ambient).
Crossfade at Boundaries
Overlap-add stitching at chunk edges using a 100 ms Hann window crossfade to eliminate seams between processed segments.
Demucs htdemucs UVR-MDX-NET-Voc_FT PyTorch Overlap-Add (OLA) GPU Inference
03
Voice Interface
Voice-Controlled Remixing
The user issues natural language voice commands in real time. Speech is transcribed, parsed for intent, and translated into gain parameters applied to the separated stems.
// workflow
Capture Voice Command
Record from microphone via browser API or PyAudio. VAD (Voice Activity Detection) triggers recording start/stop to avoid continuous polling.
Transcribe with Whisper
Pass voice clip to Whisper tiny/base for fast, local speech-to-text. Runs in under 300 ms for short commands on CPU.
Parse Intent
Rule-based parser maps transcribed text to commands: mute commentary, amplify crowd, boost crowd by 20%, balanced mix. Fallback to keyword matching if intent is ambiguous.
Resolve Gain Parameters
Translate parsed intent to commentary_db and crowd_db values. Pass parameters to the remix engine for the next chunk window.
Whisper tiny/base WebRTC VAD PyAudio Intent Parser Web Speech API
04
Audio Engine
Remixing & Reconstruction
Apply user-resolved gain parameters to the separated stems, mix them back into a single audio track, and remux with the delayed video stream for synchronized output.
// workflow
Apply Gain to Stems
Attenuate or amplify vocals and no_vocals stems using resolved dB values. Uses pydub AudioSegment arithmetic or raw numpy gain multiplication.
Smooth Gain Transitions
When user changes preference mid-stream, apply a linear gain ramp over 200–500 ms to avoid abrupt level jumps. Ensures perceptually smooth transitions.
Mix Stems
Overlay adjusted stems: final = crowd_adjusted.overlay(commentary_adjusted). Normalize output to prevent clipping.
Remux with Video
Attach processed audio to the delayed video stream using FFmpeg lossless copy. Output as AAC 192kbps or pass through PCM for low-latency playback.
pydub numpy FFmpeg remux Linear Gain Ramp AAC 192kbps
05
Output & Delivery
Output & Delivery
Stream the processed video+audio output to the viewer's player with a consistent 10-second lag offset. Optionally save a remixed recording for download.
// workflow
Stream to Player
Push processed chunks to the frontend video player via Flask streaming response or WebSocket. Player receives a continuous remixed stream at a stable 10s offset from live.
Optional: Save Recording
Accumulate processed chunks into a final output file. Serve as downloadable .mp4 via /media/processed/ endpoint at session end.
Cleanup
Flush temp stems and buffer files from /work/ directory after session ends. Keep final output in /processed/ for user download window.
Flask Streaming WebSocket HLS Output FFmpeg concat
